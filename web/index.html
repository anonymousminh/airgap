What a receipt proves, and what it doesn’t

It proves

  • The receipt wasn’t altered after the orchestrator issued it
  • The sandbox policy, as observed from docker inspect
  • The container was destroyed and verified gone
  • Every number in the answer appeared in the real output

It doesn’t prove

  • Hardware attestation: you trust the orchestrator’s measurements
  • That gVisor has no bugs; it’s a user-space kernel, not a microVM
  • That a script’s logic is correct, only that its numbers are real
  • That the orchestrator host is uncompromised

Questions you should ask

Does my data leave the server?

Your file is processed only on our Vultr VM. To plan and explain the analysis, the schema, five sample rows and the program’s output are sent to Vultr Serverless Inference. Don’t upload sensitive data to the public demo.

Is it unhackable?

No, and we don’t claim that. A fully compromised model still can’t reach a network, a secret or the host, and you can check that yourself. Residual risks are listed openly in the threat model.

Why gVisor and not a microVM?

The demo VM has no KVM, so Firecracker-style microVMs weren’t available. The runner sits behind an interface, so a microVM backend is a drop-in next step.

Which models does it use?

A coder model (qwen3.8-27b) writes the script; a different model (glm-5.3) writes the answer from real output. Both run on Vultr Serverless Inference.

Are the attacks real?

They’re classes of attack inspired by public incidents, executed as the code a fully hijacked model would write. Every payload is viewable in the app.

What are those animated orbs and avatars?

Border beam, thinking orbs and bot avatars come from the open-source libraries.dev packages (MIT). We use them for status, not decoration.
