Why this exists

AI analysts are useful. Unverifiable ones don’t get deployed.

Security teams block AI data tools for reasons that are easy to state and hard to check.

A cell can carry instructions

Spreadsheets are untrusted input. A single poisoned cell can hold a prompt injection aimed at making the agent read, encode and send data somewhere it shouldn’t.

Restrictions leak in quiet ways

Even sandboxes that block normal traffic have been reported leaking through side channels such as DNS lookups. “No outbound HTTP” isn’t the same as “no network”.

“Trust us” isn’t auditable

Reviewers need evidence per answer: what the sandbox could do, what it did, and that nothing was left behind. A claim on a slide isn’t evidence.

How it works

Two planes. One rule: the LLM never touches the sandbox.

  1. 1

    Upload & ask

    Your CSV is parsed by a fixed profiler inside a sandbox. The control plane never parses untrusted bytes.

  2. 2

    Plan

    A coder model on Vultr Serverless Inference writes one Python script from your question and the schema.

  3. 3

    Execute in isolation

    A fresh gVisor container: no network, no secrets, read-only filesystem, dropped capabilities, resource caps. Destroyed after.

  4. 4

    Verify & sign

    A second model writes the answer from real output. Number Guard checks every figure. The receipt is signed and chained.

Straight talk

What a receipt proves — and what it doesn’t.

It proves

  • The receipt wasn’t altered after the orchestrator issued it
  • The sandbox policy as observed from docker inspect
  • The container was destroyed and verified gone
  • Every number in the answer appeared in the real output

It doesn’t prove

  • Hardware attestation — you trust the orchestrator’s measurements
  • That gVisor has no bugs; it’s a user-space kernel, not a microVM
  • That a script’s logic is correct — only that its numbers are real
  • That the orchestrator host is uncompromised

The full list of risks and mitigations is in the threat model.

FAQ

Questions you should ask.

Does my data leave the server?

Your file is processed only on our Vultr VM. To plan and explain the analysis, the schema, five sample rows and the program’s output are sent to Vultr Serverless Inference. Don’t upload sensitive data to the public demo.

Is it unhackable?

No, and we don’t claim that. It’s built so that a fully compromised model still can’t reach a network, a secret or the host, and so you can check that for yourself. The residual risks are listed openly in the threat model.

Why gVisor and not a microVM?

The demo VM has no KVM, so Firecracker-style microVMs weren’t available. The runner is behind an interface, so a microVM backend is a drop-in next step.

Which models does it use?

A coder model (qwen3.8-27b) writes the script and a different model (glm-5.3), both through Vultr Serverless Inference, writes the answer from the real output.

Are the attacks real?

They’re classes of attack inspired by public incidents, executed as the code a fully hijacked model would write — not reproductions of any vendor’s exact exploit. You can read every payload in the app.

Can I run it myself?

Yes. It’s MIT licensed: github.com/anonymousminh/airgap.
