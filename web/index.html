    How it works
    Two planes. One rule: the LLM never touches the sandbox.
    
    
    
      
    
        
    CONTROL PLANE · Vultr Cloud Compute VM · trusted
          
    FastAPI orchestratorVultr Serverless InferenceNumber GuardEd25519 signerhash-chained ledgerDocker + gVisor driver
    
        
    TRUST BOUNDARY
    
        
    DATA PLANE · one throwaway container per run · untrusted
          
    network = noneread-only rootfscap-drop ALLno-new-privilegesnon-rootpids / mem / cpu / wall capsdestroyed & verified
    
      
    
      
    Plan
    A coder model writes one Python script from your question and a sandbox-parsed schema. Untrusted cell text is treated as data.
    
      
    Dispatch
    The script runs in a fresh gVisor container with no network, no secrets and no Docker socket. Only stdout and PNGs come back.
    
      
    Prove
    A second, different model explains the result. Number Guard checks every figure against real output. The receipt is signed and chained.
    
      
    
        
    What we do not claim
    
        
    The signature proves the receipt wasn’t altered after the orchestrator issued it. It is not hardware attestation — you are trusting the orchestrator’s measurements. Attack payloads are the code a fully hijacked model would write, executed deterministically; they are classes of attack inspired by public incidents (ChatGPT code interpreter, Flowise CSV agent, AWS Bedrock code interpreter), not reproductions of vendors’ exact exploits.
